    Bus Monitor

    Frame-level Modbus trace — the exact bytes on the wire, one row per transaction (every retry included). Runtime only: the buffer lives in memory and capture stops on restart.

    Register Probe

    One-shot read on any Modbus device with every interpretation side by side — data type × word order (ABCD / CDAB / BADC / DCBA). Read-only. With the capture running, the probe's frames show up in the monitor above, exception replies included.

    SunSpec Scan

    Walks the SunSpec model chain (the SunS marker at 40000/50000/0, then every model the device declares) — identity, meters, MPPT, storage. Read-only; works on most Fronius / SMA / SolarEdge / Huawei / ABB inverters and SunSpec meters.

    Backup & Restore

    Download a ZIP with all devices, measurement selections, device templates and virtual meters — or restore one. Secrets and network settings are excluded by default.

    Snapshots & Rollback

    A snapshot of the full config is taken automatically after every change (devices, measurements, templates, virtual meters, settings). Restore rolls everything back to that moment — the current state is snapshotted first, so a rollback is itself reversible. “Last known good” updates only after a healthy boot and restores automatically if the config no longer loads.

    Service tokens

    For programs, not people: a companion service or a script signs in with a named token (sent as Authorization: Bearer). It has a role like a login, the audit log shows its name, and revoking it touches no one's password. The token is shown once, when it is made.

    Modbus writes

    Off by default — this is the master arming switch; writing to real hardware is irreversible. When on, any device that is not write-locked can be written: declared registers use their template encoding and enforce whatever guards you declared (min/max/allowed — each guard you declare buys enforcement and a better write dialog), and undeclared registers accept a raw write after an explicit unguarded acknowledgement. Every write is confirmed, authenticated, rate-limited and audited. The primary device ships write-locked.

    Alerts

    Alerts delivered over MQTT and/or an HTTP webhook: infrastructure health (a device or sink drops, latency spikes, the InfluxDB buffer backs up), the alarms a device's template declares (an error code, a fault word), and optionally the per-register value thresholds. Applied live on save.

    Signals

    Channels

    Empty = webhook off. POSTs the alert JSON here (no LAN restriction — meant for external notifiers).

    Placeholders: {severity} {source} {message} {key} {host} {ts}. Empty = raw alert JSON.

    Rules

    A rule decides when a command runs: it watches live values, waits for them to settle, and asks a device for what it wants. A new rule runs in shadow — it decides and says so, but writes nothing — until you arm it.

    Export

    Sequences

    Commands in order, with waits and checks — undone in reverse when a step fails or you cancel. Each command meets every gate of a command; a safety rule holding a device still stops it.

    Virtual Meters

    Serve a device's live values as a standard Modbus meter so other systems read them natively (EM24 → Victron grid meter, Fronius Smart Meter → DataManager). Enable only to validate in parallel with the real meter — this feeds a control-critical reference.

    Templates

    The catalog behind your devices. Device maps tell the gateway how to read a real meter (register addresses, function code, byte order). Meter emulations re-serve live values as a standard Modbus meter. Bundle, upload, import from CSV, edit and share them here.

      Import register map from CSV

      A CSV register list from a vendor or the community becomes a device template. Columns are matched loosely — address and name are required; label, unit, type, scale, category, json_path are optional. Address accepts decimal or 0x hex.

      A community/vendor YAML register map becomes a device template. Accepts a bare list, a registers: list, or a device_template: wrapper. Richer than CSV — per-register enum, bits, thresholds and the write envelope pass through untouched. Field names are matched loosely (reg/addr, type/datatype, factor/gain).

      The manual says it as "word order", "swapped", "LSW first" or shows a float example. Unsure? Import with ABCD, then Diagnostics → Probe shows which order gives a sane value; change it in the template editor.
